# ADR-021: Las métricas de la API salen por OTLP, empujadas

- Status: accepted (decisión confirmada por la persona responsable del producto el 2026-10-07; evidencia de implementación registrada por lote)
- Change: producto-monitorizacion-final
- Date: 2026-10-07
- Complementa: [ADR-011](ADR-011.md) y [ADR-020](ADR-020.md).

## Context
La API calcula sus métricas con `System.Diagnostics.Metrics` (`Monitoring.Pipeline`, `Monitoring.Ingestion`, `Monitoring.Probes`, `Monitoring.Retention`), pero ningún exportador las sacaba del proceso: no había endpoint `/metrics` ni exportación OTLP. Las reglas sobre ellas solo se comprobaban contra el texto del código, y ninguna plataforma podía evaluarlas. [ADR-011](ADR-011.md) manda usar las convenciones de OpenTelemetry «para desacoplar la instrumentación del destino» y comprobar la compatibilidad de la plataforma antes de elegir exportadores; no consta cuál es la plataforma corporativa (G-07).

## Decision
La API exporta por OTLP/HTTP (protobuf) con el SDK de OpenTelemetry (`OpenTelemetry.Extensions.Hosting` y `OpenTelemetry.Exporter.OpenTelemetryProtocol`, versiones estables), registrando todos los medidores `Monitoring.*`.
- **Opt-in.** Solo si `Telemetry:Otlp:Endpoint` está configurado; sin él no se exporta ni se abre conexión alguna. Un valor que no sea una URL http(s) absoluta detiene el arranque, porque un error tipográfico desactivaría en silencio las alertas que dependen de estas métricas.
- **Intervalo** configurable (`Telemetry:Otlp:ExportIntervalSeconds`, 15 s por defecto).
- **Destino.** Producción: el colector OTLP corporativo, o Prometheus 3 con su receptor OTLP nativo. Laboratorio: el Prometheus de [ADR-020](ADR-020.md).
- **Sin superficie nueva.** La API no expone un endpoint de métricas que haya que proteger.

## Alternatives
- **Endpoint `/metrics` por scrape** (`OpenTelemetry.Exporter.Prometheus.AspNetCore`): solo existe como versión beta, ata la API a un modelo de scrape y añade una superficie HTTP que autenticar. Los nombres saldrían ya en formato Prometheus, lo que simplificaba las reglas.
- **Posponer hasta conocer la plataforma:** deja las reglas sin evaluar hasta G-07 y retrasa la evidencia que S17 necesita.

## Consequences
- La traducción OTLP→Prometheus puede cambiar nombres. Se verificó en un Prometheus real: los medidores observables llegan con su nombre (`monitoring_pipeline_wal_slot_active`, `monitoring_search_freshness_lag_seconds`…) y coinciden con los de las reglas. Los contadores y medidas sin valor no aparecen hasta que ocurren; las reglas `absent()` deben leerse con ello en cuenta.
- Las métricas de la sonda (`monitoring_probe_*`) las produce otro proceso, que todavía no exporta; sus reglas quedan sin datos hasta que la sonda incorpore el mismo exportador.
- Una dependencia más en la API (SDK de OpenTelemetry), mantenida por la CNCF.
- Una caída del destino no debe afectar a la API: el exportador corre en su propio hilo y, si el envío falla, pierde ese intervalo y lo intenta en el siguiente. Se comprueba parando el destino en el ensayo del laboratorio.

## Reversion
Quitar `AddMonitoringTelemetry` y los dos paquetes; los medidores siguen existiendo y no cambia ningún contrato. Si la plataforma corporativa exige scrape, añadir el exportador Prometheus conservando los mismos nombres de medidor.
