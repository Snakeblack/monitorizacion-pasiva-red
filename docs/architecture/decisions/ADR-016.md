# ADR-016: Revisiones semánticas y barreras sin resurrección

- Status: accepted (arquitectura adoptada; evidencia de implementación y aptitud registrada por lote)
- Change: producto-monitorizacion-final
- Date: 2026-10-05

## Context
Replay/snapshot puede asignar offsets nuevos a contenido antiguo. El contrato exige preservar revisión vigente y supresión, incluidos cursores abiertos y restauración.

## Decision
PK triple/documentKey base64url por segmentos; bigint monotónico por identidad. EventRouter agrega revision numérica como header; sink INSERT/key.ignore=false/external.version.header=revision. Delete es reemplazo mínimo operation=delete, sin IP/payload, preservando barrera permanente hasta horizonte seguro. Índices regulares strict; no data streams. Sucesor vivo ADR-016.

## Alternatives
- Offset como versión: replay republicado puede superar supresión.
- HTTP DELETE/null tombstone: una vez perdida versión de borrado, documento viejo puede volver.
- UPSERT parcial: no usa external version y deja campos anteriores.

## Consequences
Barreras añaden almacenamiento mínimo y política de purga ratificada. API comprueba visibilidad actual en PostgreSQL. Rebuild genera outbox de generación con revisión original, copia cambios por identidad de registro y cambia alias solo tras validación. Dup/old version conflict es inocuo; DLQ no es aplicada. Verificar con conector16 real el replay con offset mayor y revisión menor.
