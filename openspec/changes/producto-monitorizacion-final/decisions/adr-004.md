# ADR-004: Keycloak humano y EJBCA de máquinas

- Status: proposed (registro para promoción; elección aprobada en state.yaml)
- Change: producto-monitorizacion-final
- Date: 2026-10-05

## Context
El alcance adopta IdP/CA concretos y separa lectura/administración de entrega. Cada operación requiere ámbitos actuales; revocación desconocida no puede aceptar lotes.

## Decision
Keycloak26.7.5, OIDC Authorization Code PKCE S256 en cliente público y API issuer/audience/firma/expiración. Roles/pares validados y consulta de asignaciones actuales. EJBCA Community9.6.3 emite clientAuth; registro issuer+serial/fingerprint/SAN liga sonda a ámbito. CRL firmada≤5min y nextUpdate, fallo cerrado. TLS1.2+ validado en todos los saltos, redes privadas y credenciales por función. Sucesor vivo ADR-018.

## Alternatives
- Cabeceras/CN solamente: cliente puede suplantar identidad o ámbito.
- Tokens humanos en ingestión/certificados para lectura: mezcla funciones.
- CA estática: no evidencia ciclo EJBCA; EST Enterprise: dependencia no adoptada.

## Consequences
Tokens solo memoria, logout limpia datos/cursor; auditoría mínima sin PII de tráfico/secretos. Bootstrap CA protegido, perfiles/enrollment Community y CLI local operada. Keycloak/CA indisponible sin confianza vigente deniega. Config productiva mezcla con contexto de prueba impide arranque. Se prueban matriz, rotación/revocación/backlog y compatibilidad EJBCA/PG18 real.
